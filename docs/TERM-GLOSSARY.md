# 📖 术语大白话字典

> 给**零编程基础**同学的生存手册。每个术语配一个生活化类比 + Git 命令例子，看完就能跟学长学姐吹牛。

---

## 📁 仓库（Repository / Repo）

**是什么**：放你代码 + 文档的"文件夹"，但它有**版本记忆**。

**类比**：把它当成**一本带历史草稿本和修订记录的"作业本"**。老师让你交期末作业，你不光交了最终稿，草稿本里从第一稿到最终稿的每一步修改都留着，老师可以随时翻你中间改了啥。

**为什么需要**：
- 你的实验报告、代码、心得都在里面
- 推到 GitHub 之后就是一份**求职作品集**

---

## 📝 Commit（提交）

**是什么**：拍一次"项目当前状态的快照"。

**类比**：写作文时，每改完一版就 **Ctrl+S 另存为** 一份，但每份都取个名字（"v1-初稿" / "v2-改错字" / "v3-加论据"）。**Commit 就是带名字的"另存为"**。

**命令示例**：
```bash
git commit -m "week-03: 完成运算符练习"
```
- `git commit` = 拍照
- `-m` = 后面引号里是这次照片的标题

**生活比喻**：
> 你在朋友圈发了张照片 → 这张照片里包含文字 + 图片 + 标签 + 时间 → 这就是一次 commit。

---

## 🚫 .gitignore（忽略清单）

**是什么**：一个**黑名单**文件，告诉 Git 哪些文件**别管**。

**类比**：把 `.gitignore` 想成"**快递打包的免责声明**"。你寄物品给远方的同学，你写"贵重易碎品别寄、空的化妆品空瓶别寄、超市小票别寄"——这些"别寄单"就是 `.gitignore`。

**常见要忽略的东西**：
| 模式 | 忽略什么 | 类比 |
|---|---|---|
| `node_modules/` | Node.js 第三方代码 | 收到的赠品别再转送给别人 |
| `__pycache__/` | Python 自动生成的"中间码" | word 自动存的 `~$xxx.docx` |
| `.DS_Store` | macOS 给每个文件夹建的"小账本" | Win 桌面自动建的 `desktop.ini` |
| `.env` | 你的密码、API 密钥 | **绝对不能寄出去** |
| `*.log` | 程序运行时写的日志 | 手机自动生成的运行报告 |

**为什么不一股脑全 push？**
- 体积膨胀（`node_modules` 一个项目几百 MB）
- 含**敏感信息**（密码、token）
- 不是你自己写的（重复传别人的代码是浪费带宽）

---

## 🌿 Branch（分支）

**是什么**：从主线**复制**出去的一条平行时间线，可以做实验，玩坏了也不会影响主线。

**类比**：你家装修——主线是"日常住的房子"，分支是"改造的样板房"。你在样板房里折腾：换地板、刷墙漆、装智能马桶……改坏了大不了推倒重做，**原来住的房子纹丝不动**。

**为什么需要**：
- 多人协作不打架（每人一个分支）
- 实验性修改不污染主线
- 出问题随时 `git checkout main` 退回安全区

**常见动作**：
```bash
git branch demo                 # 看看现在有哪些分支
git checkout -b week-15-demo    # 新建并切换到 week-15-demo 分支
git checkout main               # 回到主线
```

## ⬆️ push / ⬇️ pull / 📥 clone

| 命令 | 干啥 | 类比 |
|---|---|---|
| `git push` | 把本地改动**上传**到 GitHub | 把本地的草稿本**寄回去**给老师 |
| `git pull` | 把 GitHub 上的新改动**拉**下来 | 老师批改后把红笔批注**寄回来**给你 |
| `git clone` | 把整个仓库**复制**一份到本地 | 复印整本作业本到本地 |

**最常用的就是**：
- 你改了文件 → `git push`（寄作业）
- 同学改了文件 → `git pull`（收作业）
- 第一次接触仓库 → `git clone`（复印）

---

## 🔄 Fork / Pull Request（PR）

**这是进阶篇，刚入门用不到**

- **Fork**：把别人的仓库**复刻**一份到自己名下（"借书抄一本"）
- **Pull Request (PR)**：抄完之后想"还回去给你"——这就是 PR

本课程用不到，但等你以后参与开源项目（Open Source）就要会。

---

## 📦 Module / Package（模块 / 包）

**是什么**：别人写好的代码，打包成"乐高积木"给你直接拼。

**类比**：你想做饭，与其自己种菜养鸡，不如去超市买**预制菜 / 火锅底料**——`import` 就是"开超市"。

```python
import random       # 装"随机抽奖机"
print(random.randint(1, 100))
```

---

## 🐛 Debug（调试）

**是什么**：你的代码不按预期运行时，**找到 bug 并修掉**。

**类比**：修东西——找哪里坏了 → 拆开检查 → 修 → 装回去测一遍。Debug 就是程序员版本的修电器。

**入门级 debug 武器**：
- `print("我到了这里")` 在关键位置插旗子
- VS Code 的"打断点"（红点）+ 逐步执行（F10）

---

## 🆚 IDE vs. Editor vs. Terminal

| 名称 | 干啥 | 类比 |
|---|---|---|
| **IDE**（集成开发环境） | 写代码 + 跑代码 + 调试 + 管理项目，**全家桶** | 全自动厨房（带烤箱、洗碗机） |
| **Editor** | 只负责**写**代码，没有跑 | 切菜砧板 |
| **Terminal**（终端） | 一行一行敲命令与电脑对话 | 厨房里点菜服务员 |

**推荐**：
- 新手 IDE：VS Code（轻量）/ PyCharm Community（重但全能）
- 终端：PowerShell（Win）/ Bash（macOS/Linux）

## 📌 一图总览（Git 工作流）

```
                ┌─────────────┐
                │  Working    │ ← 你正在改的本地文件
                │   Area      │
                └──────┬──────┘
                       │ git add .
                       ▼
                ┌─────────────┐
                │  Staging    │ ← "排队上车"暂存区
                │   Area      │
                └──────┬──────┘
                       │ git commit -m "xxx"
                       ▼
                ┌─────────────┐
                │  Local Repo │ ← 你的本地仓库（.git/）
                └──────┬──────┘
                       │ git push
                       ▼
                ┌─────────────┐
                │ Remote Repo │ ← GitHub 上的远程仓库
                └─────────────┘
```
